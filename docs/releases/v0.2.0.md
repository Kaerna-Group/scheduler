# Scheduler v0.2.0

## Изменения

- Единое хранение edit token: по умолчанию только в текущей вкладке; постоянное сохранение требует явной галочки. Импорт, настройки, история и admin-панель используют один механизм. Старые автоматически сохранённые токены переносятся в текущую сессию, без автоматического согласия на постоянное хранение.
- Последовательные миграции Apps Script с проверкой версии, предварительной проверкой таблиц и журналом восстановления. Повторный запуск завершает прерванную операцию; завершённые миграции не выполняются заново. Разовые исправления расписания отделены от миграций схемы.
- Локальные браузерные тесты: 27 сценариев, 52 проверки для desktop/mobile/PWA. Покрыты PIN, навигация, пользователи, недели, предметы, настройки, токены, импорт/конфликты/undo, offline/reconnect, история синхронизации, календарь и admin-панель.
- Исправлен сброс выбранного пользователя при переходе в настройки/импорт.
- Исправлено горизонтальное переполнение редактора импорта на мобильных экранах.
- Версия в настройках теперь берётся из `package.json`.

## Проверка и публикация

- Общая проверка: TypeScript, lint, 485 unit/integration/contract-тестов, 7 дополнительных Apps Script suites, production-сборка, проверка PWA и backend bundle.
- Перед выпуском все 52 браузерные проверки выполнены дважды: **104/104 passed**, без повторов после ошибок. `npm audit` не обнаружил известных уязвимостей.
- Браузерные тесты запускаются отдельно через `npm run test:e2e`; они **не добавлены в CI** и не обращаются к рабочей Google Sheets базе.
- Frontend публикуется существующим GitHub Pages workflow; Apps Script обновляется в существующем web-app deployment, без изменения URL.
- API остаётся версии **1**, схема Google Sheets — **2**. Для уже исправной схемы 2 запускать миграцию при этом выпуске не требуется. Данные расписания и серверные токены не изменяются.

## Важные ограничения

- PIN — локальная блокировка интерфейса, не серверная авторизация. Права на запись по-прежнему проверяет backend по edit token.
- Запись, импорт, undo и восстановление после сбоев проверяются на изолированной тестовой базе. Проверки рабочего сайта не должны изменять пользовательские данные.
- Перед будущей миграцией нужна резервная копия Google Sheets. Журнал восстановления ограничен 200 KB; слишком большой план отклоняется до изменения таблиц. Подробности: `apps-script/README.md`.
