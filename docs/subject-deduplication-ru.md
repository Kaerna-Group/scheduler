# Объединение дублей дисциплин

Объединение оставляет одну карточку в `Subjects` и переводит ссылки `Offerings.subject_id`
на неё. Название, сокращение и цвет берутся из оставленной карточки. Занятия, их недели,
группы, коды курсов, записи пользователей и настройки сохраняются.

Одинаковыми считаются названия после нормализации Unicode, пробелов и регистра.
Сходные названия, переводы и разные дисциплины автоматически не объединяются.
Ссылки на архивные семестры блокируют объединение, чтобы сохранить исторические данные.

## Запуск владельцем из Apps Script

Этот способ не требует ключа MCP/CLI или `SpreadsheetApp.getUi()`.
Нужен доступ владельца к редактору уже опубликованного backend.

1. Перезагрузи редактор после обновления кода.
2. Выбери **`previewSchedulerSubjectDeduplication` → Выполнить**.
   Функция при необходимости добавит служебные листы и сохранит план, но не изменит расписание.
3. В журнале проверь `commands`: `targetSubjectId` — оставляемая карточка,
   `sourceSubjectIds` — её дубли. По умолчанию сохраняется первая активная строка каждого
   одинакового названия в текущем порядке `Subjects`. В `changes` видны точные изменения
   карточек и ссылок; `affectedUsers` показывает пользователей с изменившимся представлением данных.
4. Если план соответствует нужному объединению, в течение **15 минут** выбери
   **`applySchedulerSubjectDeduplication` → Выполнить**. Запуск этой функции подтверждает сохранённый план.
5. В результате должно быть **`verification.verified: true`**. Обнови таблицу и сайт.

При `STALE_DATA` или `PLAN_EXPIRED` снова выполни предварительный просмотр.
При потере ответа после применения повтори именно `applySchedulerSubjectDeduplication`:
она использует прежний идентификатор операции и не повторяет запись.
При `verification.verified: false` проверь изменения после операции; не повторяй исправление вслепую.

Для отмены последней операции, если расписание с тех пор не менялось, выполни
`previewSchedulerSubjectDeduplicationUndo`, проверь план и затем
`applySchedulerSubjectDeduplication`. В журнале сохранены исходные строки и точные изменения.
Эти функции доступны только через редактор/авторизованное выполнение Apps Script;
HTTP-инструменты не могут выдать себя за служебную личность владельца.

## Через CLI или MCP

В файл команды для CLI или параметр `commands` инструмента `scheduler_changes_plan` передай:

```json
{
  "commands": [
    {
      "type": "subject.merge",
      "targetSubjectId": "SUB-KEEP",
      "sourceSubjectIds": ["SUB-DUPLICATE"]
    }
  ],
  "reason": "Объединение проверенных дублей дисциплины"
}
```

Замени примерные ID результатами каталога. После просмотра конкретного плана используется
обычный порядок применения с подтверждением и проверки. Интеграция должна иметь
`catalog:read`, `users:read`, `catalog:write`, `history:read`; для отмены — также `changes:undo`.

Обновлённый импорт использует существующую карточку с тем же названием в текущем семестре,
даже если в файле другой код курса. При нескольких подходящих карточках он возвращает
`AMBIGUOUS_SUBJECT` до записи. Курсы с разными кодами продолжают храниться в `Offerings`;
объединение справочника не переносит пользователя между ними. Смена курса и группы —
отдельная операция с записями `Enrollments`.
