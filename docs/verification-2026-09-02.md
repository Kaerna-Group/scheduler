## Девять пунктов

| Пункт | Реализация и проверка |
| --- | --- |
| 1. CI и package.json | Единый `check`: typecheck → lint → test → build → Apps Script bundle. Workflow использует `npm ci` и тот же `check`. Локальный прогон успешен; результат удалённого прогона доступен в GitHub Actions. |
| 2. Настройки | `UserPreferences`, связь через `user_id`, собственная revision, идемпотентное обновление схемы. Проверены авторизация владельца, конфликты, миграции и целостность. |
| 3. Старый slug | Совместимость со старым именем сосредоточена в однократной миграции localStorage v2, без специальных веток в repository/useSchedule. Есть регрессионные тесты миграции. |
| 4. Offline/stale | Различаются актуальные, кешированные/офлайн, несинхронизированные данные и недоступный backend. Настройки повторно отправляются после восстановления связи; временные ошибки используют задержку 2–30 секунд. Проверены отмена старых запросов, смена пользователя/токена, сохранность нового черновика и отсутствие повторов при отказе в доступе. |
| 5. Diff-editor | Новые предметы/занятия, изменения занятий, удаляемые записи на предметы, общие конфликты. Сквозной DOM/API-тест выбирает `apply` для одного предмета и `keep` для другого и проверяет фактический результат в базе. |
| 6. История | Страница Changes, читаемые изменения, автор и revision, фильтрация истории по пользователю/семестру и безопасный кеш. Проверены история общих занятий и исключение чужих личных данных. |
| 7. Undo | Восстановление последнего импорта, серверные проверки роли/владельца/revision, новая запись аудита. Сквозной тест сравнивает восстановленные Lessons и Enrollments с исходными. Кнопка и обработчик заблокированы офлайн. |
| 8. Семестры | Несколько семестров, `currentSemesterId`, архив, создание из предыдущего и переключатель. Проверено копирование Subjects/Offerings без Lessons/Groups/Enrollments; архив доступен только для чтения. Управление находится в Admin → System. |
| 9. Admin | Overview, Users, Audit, System. Проверены пользователи, роли, active/inactive, ротация токенов, полный каталог записей на предметы, диагностика, аудит и управление семестрами. |

Автоматический повтор записей применяется только к идемпотентным настройкам. Импорт, Undo и административные изменения требуют подключения, подтверждения и актуальной revision: после неопределённой сетевой ошибки они не воспроизводятся автоматически.

## Дополнительная проверка admin-панели

- Сервер заново проверяет активного администратора по токену на каждом admin-запросе; выбранный профиль и PIN не дают эти права.
- Admin endpoints доступны только через POST. Токены не передаются в URL.
- Защищены последний активный администратор, неизменяемые slug/id, конфликт revision, повторное нажатие и устаревшие ответы.
- Деактивация сохраняет связанные записи, но сразу запрещает доступ. Реактивация по умолчанию создаёт новый токен.
- Созданные/обновлённые токены показываются один раз; чужие токены и admin-ответы не попадают в localStorage или очередь офлайн.
- Саморотация обновляет сессию; самопонижение роли и отказ сервера в доступе очищают приватное состояние.
- Сквозной тест проходит создание пользователя → записи на предметы → роль → ротация → деактивация → реактивация → аудит.
- Отдельный сквозной тест создаёт семестр из предыдущего, меняет текущий и архивирует старый.
- Устаревший backend получает понятное сообщение о необходимости публикации. После неудачной backend-проверки интерфейс не показывает старый снимок как успешно проверенный сейчас.

## Граница проверки

DOM-тесты соединяют настоящие React-компоненты, hooks и repositories с настоящим Apps Script API, авторизацией и валидацией. Только Google Sheets/LockService/Utilities заменены изолированной средой в памяти. Внешние адреса в этой среде запрещены; реальные Google credentials не нужны.

Во встроенном браузере пользователь прошёл PIN. Проверены экран проверки admin-токена и его отображение при ширине 390 px; размер окна затем восстановлен. Локальный адрес backend добавлен в игнорируемый `.env.local`. Полный ручной проход авторизованной панели против Google Sheets **ещё не выполнен**: требуется вход пользователя. Реальные пользователи, токены, роли, семестры и расписания для тестов не изменялись.

Предупреждения сборки не блокируют результат: два намеренно ранних обычных bootstrap-скрипта и основной JS-файл около 506 kB. Admin-панель загружается отдельным модулем.

## Публикация backend

После разрешения пользователя 2 сентября опубликована **версия 8** в существующий deployment с сохранением URL. Перед загрузкой сохранена отдельная локальная резервная копия удалённого проекта; diff содержит только ожидаемые admin-изменения, без потери удалённого кода.

Проверка рабочего `/exec` после обновления: health `ok`, schema `2`, расписание и история доступны; `adminOverview` без токена возвращает `UNAUTHORIZED` вместо `UNKNOWN_ACTION`. До и после публикации одинаковы revision `8`, 8 предметов, 14 занятий и preferencesRevision `4`. Миграции, восстановление seed и изменения рабочих записей не запускались.

Frontend публикуется из `main` через [Deploy to GitHub Pages](https://github.com/Kaerna-Group/scheduler/actions/workflows/deploy.yml); результат конкретного запуска и его коммит проверяются после push. Локальные credentials, `.env.local`, сборки и резервные копии исключены из Git.
